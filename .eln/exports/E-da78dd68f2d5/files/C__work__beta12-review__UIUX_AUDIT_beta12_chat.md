# Miasma beta12 実チャット / グループチャット UI/UX 監査

- 日時: 2026-10-26（JST）
- 対象: Miasma v0.3.2-beta.12 · 179f72332（テクニカルベータ版）、表示モード=テクニカル
- 方法: 実データのバックアップ（2026-10-26 08:42時点）のコピーを専用 data-dir として監査用インスタンスを起動し、UIAツリー＋実解像度キャプチャで検証。ユーザーの許可のもと、テスト会話（グループ1件・個人2件）へ実際に送信して確認した（短文、Enter送信、158字の長文）。グループ作成・メンバー除外・履歴削除は実行していない。
- 本書は前回監査（UIUX_AUDIT_beta12.md）への追加分で、実チャット/グループチャット機能に絞る。前回指摘は修正中とのため再掲しない。

## 高

### C-H1. グループで「当日」送信した自分のメッセージの配送ステータスが切れて「待機中」しか見えない
- 再現3/3（短文・Enter送信・長文すべて）。送信直後の自分のメッセージの下には時刻と「待機中」だけが表示され、「2人中0人に届きました（待機中）」の人数部分が見えない。
- UIA実測: 当該テキスト要素の可視幅は39px（全文は名前として保持されているが描画領域が39px分しかない）。過去の自分のメッセージ（日付+時刻表示）では同じ要素が198pxで全文表示される。
- 対照実験: 1対1では当日の送信でも「送信済み（相手に届くのを待っています）」が247pxで全文表示され、切れない。グループ側のステータス行レイアウト固有の問題とみられる。
- 証拠: chat_group_after_send.png / chat_group_long.png（いずれも自分の新着メッセージ下に「10:51 待機中」「10:53 待機中」とだけ表示）。

### C-H2. メッセージ表示領域の縦が固定で小さく、ウィンドウ下部の余白が活用されない
- 実測（UIA）: 一覧スクロール領域の高さはグループ約192px、1対1約292px。ウィンドウ高719pxでもこの高さで、入力欄とファイル注記の下に約100〜170pxの空白が残る。
- 長文1件（5行バブル）でグループの表示領域がほぼ埋まり、履歴は常時スクロールしないと読めない。
- グループと1対1で高さ自体が違う（192 vs 292）点も含め、レイアウトの再配分が必要。
- 証拠: chat_group_conv.png / chat_group_long.png / chat_dm_conv.png。

## 中

### C-M1. グループ情報の下部（退出・履歴削除・説明文）がデフォルトサイズで見切れる
- 初期表示では「メンバーを追加」までしか見えず、「このグループから退出する」「このグループの履歴をこの端末から削除する」とその説明文は画面外（UIA実測で説明文は相対711〜730px位置、ウィンドウ高719pxをはみ出す）。
- スクロールすれば届くが、到達可能性の示唆が弱い（細いスクロールバー頼み）。危険操作への導線が「存在しない」ように見える。
- 証拠: chat_group_info.png（下端にボタンの上辺だけが覗く）。

### C-M2. グループ情報のメンバー状態文が1行で省略され、理由が最後まで読めない
- 例: 「メンバー - 確認済みの連絡先 - 相手に届きません: 相手がオフラインのよう…」と途中で「…」になる（UIA上は全文あり）。届かない理由という重要情報なので、折り返し表示かツールチップが欲しい。
- 証拠: chat_group_info.png。

### C-M3. 1対1ヘッダの状態表示「追加の保護を準備中…」の意味が伝わらない
- 会話を開くと名前の下に常時表示。送信後は「相手がメッセージを受け取るのを待っています · 追加の保護を準備中…」と2つの状態が「·」連結で1行表示される。
- 「追加の保護」が何を指すか（セッション暗号の確立？）、いつ完了するのか、完了したら表示がどう変わるのかがUIからは分からない。テクニカル表示なら用語の説明、かんたん表示なら言い換えが要る。

### C-M4. グループと1対1で操作の作法が不統一
- ファイル送信の場所: 1対1=入力欄の左にクリップアイコンボタン。グループ=入力欄の下に注記文＋別ボタン。同じ「ファイルを送る」行為の置き場所が会話種別で違う。
- ボタン/入力欄の accessible name が違う: グループ=「グループにメッセージを送る」「グループへのメッセージ入力欄」、1対1=「メッセージを送信」「メッセージを入力」。支援技術利用者には別物に聞こえる。
- 右上のボタン: グループ=情報（i）アイコン、1対1=「…」（その他の操作）メニュー。役割の想起しやすさが異なる。
- 表示名と accessible name の不一致もある（画面表示「新しいグループ」/ UIA名「新しいグループを作る」）。読み上げと目視で指す名前がずれると、音声操作やサポート時の指示が噛み合わない。

### C-M5. グループの会話画面には未達時の説明がない
- 1対1では最新メッセージの下に「相手がオンラインになると届きます。」と理由＋見通しが出る。グループでは会話画面上の手がかりは「（待機中）」のみで、保管・再送の説明はグループ情報画面のバナーまで行かないと読めない（しかもC-H1で当日のステータス自体が切れる）。

### C-M6. 自分の長文バブル内テキストが右寄せで読みにくい
- 5行の長文で各行が右揃えになる。日本語の長文は左寄せが読みやすいのが通例で、他者バブル（左寄せ）とも不揃い。
- 証拠: chat_group_long.png。

## 低

- C-L1. 一覧の見出し階層が「会話 > グループ / 個人」で、グループが個人より上に来る。意図はあり得るが、初見では並びの理由が伝わりにくい。
- C-L2. 「新しい会話」ダイアログの連絡先ボタンの幅が名前依存で不揃い（実測96px / 102px）。一覧として揃えた方が整って見える。証拠: chat_dialog_new_conv.png。
- C-L3. 会話一覧に検索欄がない。連絡先が増えた段階で目当ての会話を探しにくくなる。
- C-L4. メンバーメニュー（管理者向け）の破壊的操作が「外す」の一語のみ。対象や結果の補足がない（実行していないため確認ダイアログの有無は未確認）。
- C-L5. 日付の区切り見出しがなく、全メッセージに日時が付く（特に1対1では同日の連続メッセージでも毎回「10月23日 22:36」等）。当日=時刻のみ／過去=日付+時刻の切替自体は分かりやすいが、情報量は多め。

## 良かった点

- Enterキーで送信できる（グループ/1対1とも実送信で確認）。空入力では送信ボタンが無効。
- 長文（158字）の折り返しは正常。一覧プレビューは「…」で適切に省略され、当日の会話は「今日 10:53」と表示される。
- 1対1の状態表現: 既読=緑のチェック、配送済み=緑文字「届きました」、未達時は「送信済み（相手に届くのを待っています）」＋理由行。段階が一目で分かる。
- グループ情報のオフラインバナー（「いま○○に届きません。送ったメッセージは保管され、相手がオンラインになったら届きます」）は理由と見通しが明確。
- グループ作成フォーム: グループ名（64字カウンタ付き）とメンバー選択の両方が必須で、片方だけでは「グループを作る」が無効、両方そろうと有効化（個別・複合の両条件を確認）。「メンバー同士が連絡先になることはない」旨のプライバシー説明も明快。
- グループでは他者のメッセージに送信者名が付き、自分のメッセージには配送状況（n人中m人に届きました）が付く設計自体は妥当（C-H1はその表示欠けの問題）。
- グループでファイルを送れないことを明示し、「連絡先にファイルを送る」代替導線を用意している。
- 履歴削除は「先にグループから退出してください」と理由付きで無効化されており、前回監査で確認した「無効理由を隣に書く」良いパターンがここでも生きている。

- 「外す」「この会話の履歴を削除」等の実行結果と確認ダイアログの有無: 破壊的操作のため実行せず。
- グループ作成の実行: フォーム検証まで（作成自体は未実施）。
- かんたん表示モードでのチャット画面: 今回はテクニカル表示のみ。
