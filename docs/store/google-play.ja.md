# Google Play 申請キット

日本語 | [English](google-play.md)

所有者向けの下書きです。内容はすべて、このリポジトリの Android のソースとスクリプト (`android/`、`scripts/build-android.sh`、`crates/miasma-ffi`) に書かれていることだけをもとにしています。README は Android 版を「まだダウンロードとして公開していない」と述べており、この資料も同じ立場です。申請を止めているものは 8 章にまとめました。[所有者] と付いた項目は判断か、実機での確認が必要です。

Android 版はデスクトップ版より小さなアプリです。画面はホーム、ファイル (届いたファイル、送ったファイル、ファイルを取り戻す)、ステータス、設定です。連絡先の画面も、チャットも、招待コードもありません。説明には実際にあるものだけを書いてください。

## 1. ストア掲載文

### アプリ名

Miasma

### 短い説明

ファイルを端末どうしで直接、プライベートに送って受け取って保存できます。

### 詳しい説明

> Miasma は、会社のサーバーにファイルを預けずに信頼できる相手へファイルを送り、自分のファイルを安全に保つためのアプリです。
>
> できること
>
> - ファイルを送る: ファイル (100 MiB まで) か文章を選び、受信者の連絡先を入力して、パスワードと受信者が取り出せる期間を決めます。受信者から届くチャレンジコードをあなたが確認します。
> - ファイルを受け取る: 自分宛てのファイルが「ファイル」に表示されます。チャレンジコードを送信者に伝え、パスワードを入力して、端末に保存します。
> - 安全に保存する: ファイルや文章を暗号化して保存します。Miasma が渡す Content ID は自分で控えておきます。QR コードとして表示もできます。
> - ファイルを取り戻す: Content ID を入力するか QR コードを読み取って、復元したファイルを端末に保存します。
> - 緊急消去: この端末のノード鍵を破棄します。ここに保存したものはすべて読めなくなります。
>
> しくみ
>
> - アカウント、広告、利用状況の分析はありません。
> - ファイルは暗号化されたまま、あなたの端末から選んだ相手に届きます。提供者がファイルを預かるサーバーを運用することはありません。
> - アプリには最初から接続するサーバーが組み込まれていません。設定に入力した相手から接続を始めます。
>
> ベータ版です
>
> Miasma はベータ版で、外部の監査を受けていません。漏れると重大な被害になる情報には使わないでください。利用する二人とも Miasma が必要です。ノードが動いている間、アプリは通知を出し続けます。Android がしばらくしてこのバックグラウンドの動作を終わらせることがあります。そのときは Miasma を開き直してください。

提出の前にこの文章をアプリと照らして確かめてください。上の文言は `android/app/src/main/res/values/strings.xml` と、`android/app/src/main/kotlin/dev/miasma/ui` の画面に沿っています。

### グラフィック素材

リポジトリに Play 用のグラフィックはありません。必要なのは、512 x 512 のアプリアイコン、1024 x 500 のフィーチャーグラフィック、実機で撮ったスマートフォンのスクリーンショットです。`web/icons/icon-512.png` は 512 x 512 で、気に入ればアイコンに使えます。[所有者] スクリーンショットにはリリースビルドを動かした実機かエミュレーターが要ります。まだ 1 枚もありません。

### プライバシーポリシー

確認が済んだ [privacy-policy.ja.md](privacy-policy.ja.md) と [privacy-policy.md](privacy-policy.md) を公開し、公開のアドレスを Play Console に入力します。

## 2. データセーフティのフォーム (下書き)

答えは、Play Console に表示される設問と、「収集」と「共有」の意味についての Google の最新のヘルプに合わせてください。私の読み方では、端末の中にとどまるデータや、利用者が自分で選んだ受信者に送るデータは開発者が収集したことになりません。[所有者] 提出の前にこの読み方を最新のヘルプで確かめてください。以下の回答は Android 版だけのものです。

回答の根拠になる事実は次のとおりです。アプリにはアカウントの仕組みがなく、広告や分析のコードがなく (`android/` とその Gradle の依存関係である Compose、AndroidX、ZXing、JNA を調べました)、開発者が運用するサーバーもありません。組み込みのノードは Rust のコアです。Android では、iroh の中継と探索の通信がオフになっている (`crates/miasma-ffi/src/lib.rs`) ので、中継サーバーにも探索サービスにも接続しません。接続を始めるのは設定に利用者が入力した相手 (初期値はありません) で、そのあとに受信者や、共有するデータが必要とする別のノードにつながります。

| セクション | 回答案 | 理由 |
|---|---|---|
| 必須のデータ種別を収集または共有するか | いいえ | 上の読み方による。[所有者] 要確認。 |
| 位置情報 | 収集しない | アプリは位置情報を読みません。 |
| 個人情報 (名前、メール、ユーザー ID、住所、電話、その他) | 収集しない | アカウントもログインもありません。 |
| 金融情報 | 収集しない | 決済はありません。 |
| 健康とフィットネス | 収集しない | ありません。 |
| メッセージ | 開発者は収集しない | 「送る」で入力した文章は、利用者が選んだ受信者に暗号化して届きます。 |
| 写真と動画、ファイルとドキュメント | 開発者は収集しない | 利用者が選んだファイルは、選んだ受信者に届きます。 |
| 音声 | 収集しない | ありません。 |
| カレンダー、連絡先 (端末の連絡先) | 収集しない | アプリは読みません。 |
| アプリのアクティビティ | 収集しない | 分析はありません。 |
| ウェブの閲覧 | 収集しない | ありません。 |
| アプリ情報とパフォーマンス (クラッシュログ、診断) | 収集しない | 開発者には何も送りません。 |
| デバイスやその他の ID | 収集しない | アプリは広告 ID も端末の ID も読みません。アプリ自身のノード ID (ピア ID) は、通信する相手に見えます。[所有者] 触れるかどうかを決めてください。 |

セキュリティの取り組みです。

| 設問 | 回答案 | 備考 |
|---|---|---|
| 転送中のデータは暗号化されている | はい | 相手との接続は QUIC で、内容は端末を出る前に暗号化されます。 |
| データの削除を依頼する方法 | 開発者は利用者のデータを持っていません。アプリ内の「緊急消去」で端末内のデータを消せ、アンインストールでも消えます。 | Play のアカウント削除の要件はアカウントに関するもので、このアプリにアカウントはありません。[所有者] 最新の Play ポリシーで確認してください。 |
| 第三者によるセキュリティ審査 | いいえ | 外部の監査は受けていません。 |
| ファミリー向けポリシーに従う | 該当しない | 子ども向けのアプリではありません。 |

保存時の暗号化について、正直に書きます。保存した共有は暗号化されています。ノード鍵の復旧用の控えは、Android Keystore の鍵で包まれています (`KeystoreHelper.kt`)。ただしノードが動いている間、Rust のコアはアプリ専用の領域にある平文の `master.key` ファイルを読みます。ファイルのコメントはこれを多層防御と位置づけ、鍵が安全なハードウェアの外に出ないという主張ではないと述べています。掲載文でそれ以上のことを言わないでください。

## 3. 権限と申告

`android/app/src/main/AndroidManifest.xml` に宣言されているものです。

| 権限 | 理由 | Console での対応 |
|---|---|---|
| `INTERNET`、`ACCESS_NETWORK_STATE` | 相手との接続 | なし。 |
| `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_DATA_SYNC` | 通知を出しながらノードを動かし続ける | `dataSync` 型のフォアグラウンドサービスの申告を完了し、利用者に見える機能を説明します。Android 15 以降は、`dataSync` のサービスが動ける時間に上限があります。サービスは `onTimeout` で止まるように作られています。 |
| `CAMERA` (機能としては必須でない) | 「スキャン」を押したときに QR コードを読む | 権限の申告のみ。アプリは起動時には許可を求めません。 |
| API 28 までの `READ_EXTERNAL_STORAGE` | 保存するファイルの読み取り | なし。 |

宣言されていないもの: `POST_NOTIFICATIONS`。Android 13 以降では利用者が通知を許可するまでフォアグラウンドサービスの通知が見えないことがあります。8 章を見てください。

`android:allowBackup="false"` です。平文の通信は組み込みのノードが使う `127.0.0.1` と `localhost` を除いて遮断されます。ファイルプロバイダーが共有するのは、`exports/` のサブフォルダーだけです。

## 4. ターゲット API、16 KiB ページ、AAB

- `compileSdk` は 36、`targetSdk` は 36、`minSdk` は 26 です (`android/app/build.gradle.kts`)。[所有者] 新しいアプリに対する Play の最新のターゲット API の要件を確認してください。このリポジトリは 36 を指定しています。
- 16 KiB のページサイズ: Android Gradle Plugin は 8.11.1 で、ネイティブライブラリは `useLegacyPackaging = false` で格納されます。`scripts/build-android.sh` は、`libmiasma_ffi.so` の ELF セグメントが 16 KiB に揃っていないとき、APK が 16 KiB で zip 整列されていないとき、出力に含まれる `.so` (JNA のライブラリを含む) のどれかが揃っていないときに、ビルドを失敗させます。リリースでは `bundletool` に `PAGE_ALIGNMENT_16K` も問い合わせ、ツールが無いか報告されないときは警告を出すだけです。[所有者] この確認はここでは実行していません。
- ABI: `arm64-v8a` と `x86_64`。32 ビットの ABI はなく、64 ビット専用のアプリとして Play に受け入れられます。
- リリースビルドは R8 による縮小 (`isMinifyEnabled`) を有効にし、規則は `android/app/proguard-rules.pro` にあります。
- バージョン: `versionCode` は `MIASMA_ANDROID_VERSION_CODE` から (既定は 1)、`versionName` は `MIASMA_ANDROID_VERSION_NAME` から (既定は 0.3.2) 決まります。Play へのアップロードごとにより大きな `versionCode` が要ります。
- アプリケーション ID: `dev.miasma`。最初のアップロードのあとは変えられません。[所有者] この ID でよいか確認してください。

## 5. 署名: Play App Signing とアップロード鍵

Play App Signing を使います。アプリ署名鍵は Google が保管します。手元に置くのはアップロード鍵で、AAB への署名に使います。

- 鍵はこのリポジトリに作ったり置いたりしないでください。この資料にも鍵は含まれていません。
- `scripts/build-android.sh --release` はアップロード鍵で署名し、環境変数を四つ必要とします。`MIASMA_ANDROID_KEYSTORE` (キーストアのパス)、`MIASMA_ANDROID_STORE_PASSWORD`、`MIASMA_ANDROID_KEY_ALIAS`、`MIASMA_ANDROID_KEY_PASSWORD` です。足りないとスクリプトは止まります。`--unsigned-release` は署名を省くもので確認専用です。
- アップロード用のキーストアは所有者が信頼できるパソコンで一度だけ作ります。たとえば `keytool -genkeypair -v -keystore <リポジトリ外のパス> -alias <alias> -keyalg RSA -keysize 2048 -validity 9125` です。ファイルとパスワードはリポジトリの外に置き、パスワード管理ツールに入れて、オフラインのバックアップも取ってください。アップロード鍵をなくしたときは、Play Console に再設定の手続きがありますが、時間がかかります。
- 出力: `android/app/build/outputs/bundle/release/app-release.aab`。

## 7. テスト段階の要件

Google には新しい個人の開発者アカウントに対するテストの要件がありました。たとえば、製品版へ進む前に一定の人数のテスターで一定の期間、クローズドテストを済ませるものです。この規則は変わります。日程を立てる前に新しい個人アカウントに対する Play Console の最新の規則を確認してください。この資料は数字を断定しません。[所有者] クローズドテストを見込み、テスト用のリンクからインストールできるテスターの一覧を用意してください。

## 8. Play への申請を止めているもの

ビルドではなく、リポジトリを読んで分かったことです。

1. README は、Android 版がソースツリーにあるが公開されていないと述べています。リポジトリの開発者向けメモは、Android 版を再現できるビルドに仕立てる途中の骨組みと位置づけています。実機での試験の記録はリポジトリにありません。[所有者 / 実機]
2. `.github/workflows` の CI は Android アプリをビルドしません (Android、Gradle、NDK で検索して、見つかりませんでした)。リリースのビルドは手作業で作って確かめる必要があります。
3. ビルドにはリポジトリに入っていないツールが要ります。Android SDK の API 36、build-tools 36.0.0、NDK 30.0.16248370、Android 向けの Rust ターゲット、`cargo-ndk`、JDK 17 以上です。`./scripts/build-android.sh --setup` が、その一部を入れます。
4. リポジトリにある `android/app/src/main/kotlin/dev/miasma/uniffi/miasma_ffi.kt` は、小さな開発用の代用品です。スクリプトはビルド中に本物のバインディングを生成し、終わったら代用品を元に戻します。
5. アップロード用のキーストアは設計上、リポジトリにありません。5 章を見てください。
6. Play 用のグラフィックも、スマートフォンのスクリーンショットもありません。
7. `POST_NOTIFICATIONS` が宣言されていません。Android 13 以降では利用者が許可するまでフォアグラウンドサービスの通知が隠れることがあります。権限とその要求を足すか、通知が隠れたままになるのを受け入れるかを決めてください。
8. Android 15 の `dataSync` サービスの時間制限: サービスは時間切れで自分で止まり、アプリは利用者に開き直すよう伝えます。実機で試験してください。[実機]
9. 多言語対応が未完です。`values-ja` はありますが、画面の一部が英語の固定文字列です (設定のタイトルとボタン、通知の「Starting...」や「Connected」など)。Web ビューの画面のマニフェスト上のラベルも、固定の「Miasma Web」です。日本語の掲載では言語が混ざったアプリに見えます。
10. 用語がデスクトップの Easy モードと違います。Android は「Content ID」「sharing contact」(`msk:...@PeerId`)「challenge code」と言います。デスクトップは「招待コード」(Share ID を指す)、「連絡先コード」、「確認コード」と言います。Android に連絡先の画面はありません。製品全体で用語をそろえたいなら公開の前に合わせてください。[所有者]
11. フォアグラウンドサービスの申告とデータセーフティのフォームは Play Console で入力する必要があり、プライバシーポリシーは公開のアドレスに置く必要があります。
12. `applicationId` の `dev.miasma` を確認してください。[所有者]
