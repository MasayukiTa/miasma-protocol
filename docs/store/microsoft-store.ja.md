# Microsoft Store 申請キット

日本語 | [English](microsoft-store.md)

所有者向けの下書きです。内容はすべて、このリポジトリのソースに書かれていることだけをもとにしています。[所有者] と付いた項目は判断か、実際の Windows パソコンでの確認が必要です。アプリの登録は後日、個人開発者アカウントで行います。

用語は Easy モードの画面に合わせています。ホーム、ファイルを送る、ファイルを受け取る、安全に保存する、連絡先、チャット、ファイル、設定、「招待コード」です。

## 1. ストア掲載文

### タイトル

Miasma

(マニフェストの `DisplayName` も `Miasma` です。Partner Center で別の名前が予約された場合は、Partner Center 側のタイトルを変え、マニフェストはそのままにします。)

### 短い説明

信頼できる相手へ直接ファイルを送り、自分のファイルも安全に保てます。アカウントは要りません。

### 詳しい説明

> Miasma は、会社のサーバーにファイルを預けずに信頼できる相手へファイルを送り、自分のファイルを安全に保つためのアプリです。
>
> あなたの Miasma と相手の Miasma が直接やり取りし、途中の通信はすべて暗号化されます。直接つなげないときは中継サーバーを使い、その理由を画面に表示します。
>
> できること
>
> - ファイルを送る: 連絡先とファイルを選んで送るだけです。アカウントも、Web サイトへのアップロードも、リンクの貼り付けも要りません。
> - ファイルを受け取る: 連絡先から届いたファイルがアプリに表示されます。招待コードで受け取ることもできます。パスワードは任意です。
> - 安全に保存する: ファイルを暗号化して自分のパソコンに保存し、あとで取り出せます。
> - チャット: 一人の相手やグループに短いメッセージを送れます。相手がオフラインのときに送ったメッセージは相手が戻るまで自分のパソコンで待機します。
> - 大きなファイル: 大きな転送を止めて、あとで止めたところから続けられます。
> - 連絡先: 連絡先コードを一度交換し、確認用コードを見比べて、相手が本人であることを確かめます。
>
> ほかとの違い
>
> - アカウント、広告、利用状況の分析はありません。提供者が運用するサーバーが、あなたのファイルを預かることもありません。
> - 設定でデータの保存場所を確認できます。完了した転送の消去、会話の履歴の削除、「緊急消去」ですべてを消すことができます。
> - 表示言語: 英語、日本語。[所有者: アプリには簡体字中国語もありますが、パッケージが宣言しているのは en-us と ja-jp だけです。5 章を見てください。]
>
> ベータ版です
>
> Miasma はベータ版で、外部の監査を受けていません。漏れると重大な被害になる情報には使わないでください。利用する二人とも Miasma のインストールが必要です。Windows 10 バージョン 2004 (ビルド 19041) 以降の 64 ビット版が必要です。

「軍事レベル」「匿名」「追跡できない」のような、アプリが裏づけられない言葉は使わないでください。Store の規約は誤解を招く表現を禁じています (最新の文面を確認してください)。実際の限界は SECURITY.md にあります。

## 2. スクリーンショット

Partner Center には、1366 x 768 以上のデスクトップ画面のスクリーンショットが少なくとも 1 枚要ります。実際の画面で、サンプルのデータだけを使ってください。実在の連絡先コードは絶対に写さないでください。

`docs/images` にある画像は、ファイルを調べたところどれも幅が 1366 ピクセルに届きません。そのままでは提出できません。拡大もしないでください。

| ファイル | 大きさ | Store での扱い |
|---|---|---|
| `docs/images/screenshot-home-en.png` | 1200 x 500 | 使えません。小さすぎます。ホームを撮り直します。 |
| `docs/images/screenshot-home-ja.png` | 1200 x 500 | 使えません。日本語のホームを撮り直します。 |
| `docs/images/screenshot-contacts-en.png` | 1200 x 900 | 使えません。連絡先を撮り直します。 |
| `docs/images/screenshot-files-en.png` | 1200 x 1010 | 使えません。ファイルを撮り直します。 |
| `docs/images/screenshot-chat-en.png` | 1200 x 900 | 使えません。チャットを撮り直します。 |
| `docs/images/screenshot-chat-list-ja.png` | 1200 x 450 | 使えません。会話の一覧を撮り直します。 |
| `docs/images/screenshot-settings-en.png` | 1200 x 430 | 使えません。設定を撮り直します。 |

README には今のまま使えます。Store 用には英語で最低でも次の 5 枚を撮り、日本語の掲載用に同じ 5 枚を日本語でも撮ってください。ホーム、連絡先、チャット、ファイル、設定です。

### UI ツアーで撮る方法

デスクトップのクレートには開発者専用の UI ツアー (`crates/miasma-desktop/src/app/tour.rs`、機能 `ui-tour`) があります。リリースには含まれません。サンプルのデータで本物の画面を描くので実在の連絡先コードは写りません。

ウィンドウなしのツアーです。手順表の大きさは固定です。幅が 1366 以上なのはチャットと連絡先だけで、チャットは 1400 x 900、連絡先は 1400 x 2100 です。

```powershell
$env:MIASMA_UI_TOUR_ALL = "1"
$env:MIASMA_UI_TOUR_FILTER = "chat_thread_light_en_wide,chat_list_light_en_wide,contacts_two_light_en_wide"
$env:MIASMA_UI_TOUR_OUT = "$env:TEMP\miasma-store-shots"
cargo test --package miasma-desktop --features ui-tour --bin miasma-desktop headless_tour_renders_every_step -- --nocapture
```

手順の名前は `chat_<fixture>_<light|dark>_<en|ja>_<wide|narrow>` と `contacts_<fixture>_...` の形です。fixture の一覧は `chat_ui::FIXTURES` と `contacts::FIXTURES` にあります。連絡先の画像は縦に長いので 1366 x 768 以上の範囲で切り抜いてください。切り抜くだけにして、拡大縮小はしないでください。

ウィンドウなしの Easy ツアーではホーム、ファイル、設定の幅が 1200 ピクセルしかなく、小さすぎます。大きく撮る方法は二つあります。

1. 画面のあるパソコンでウィンドウのツアーを動かします。指定した大きさのウィンドウで撮れ、`.ppm` ファイルが出るので PNG に変換します。

   ```powershell
   $env:MIASMA_UI_TOUR = "$env:TEMP\miasma-store-shots-gl"
   $env:MIASMA_UI_TOUR_EASY = "1"
   $env:MIASMA_UI_TOUR_SIZE = "1400x900"
   $env:MIASMA_UI_TOUR_FILTER = "light_en_home,light_en_files,light_en_settings"
   cargo run --release --package miasma-desktop --features ui-tour
   ```

2. ウィンドウなしのツアーが `MIASMA_UI_TOUR_SIZE` を読むように、小さな変更を別に加えます。このプルリクエストでは行っていません。

[所有者] これらのコマンドはこの資料を書いたときには実行していません (使った環境ではビルドが禁止されていました)。一度実行し、アップロードの前にすべての画像を開いて確かめてください。インストールしたアプリでデモ用のプロファイルを使って撮る方法でも構いません。

## 4. 制限付きの機能 runFullTrust

マニフェストは `runFullTrust` (制限付きの機能、`rescap:Capability`) を宣言しています。Partner Center でその理由の説明を求められます。回答案です。

> Miasma は Rust で書かれた Windows のデスクトッププログラムで、Desktop Bridge で完全信頼のパッケージアプリにしています。次の理由で UWP のサンドボックスでは動きません。
>
> 1. 同じパッケージに入った二つ目の実行ファイル (`miasma.exe`) を、子プロセスとして起動します。これがバックグラウンドのサービスで暗号鍵を持ち、ファイルを保存し、すべてのネットワーク接続を扱います。利用者がアプリを開くと起動し、閉じると終了します。
> 2. 利用者どうしの直接接続 (QUIC) のための UDP ソケットと、ウィンドウとサービスの間のローカルのループバック通信を開きます。
> 3. 標準の Windows のファイルダイアログで利用者が選んだ場所のファイルを読み書きします。数ギガバイトの大きなファイルも、ディスクからまたディスクへ流して処理します。
>
> ドライバーやサービスのインストール、システム設定や PATH の変更、ファイルの関連付けの登録、管理者権限の要求は行いません。Store 用のパッケージに入っているのは `miasma-desktop.exe`、`miasma.exe`、ロゴ画像だけです。

「行わないこと」は `scripts/build-store-msix.ps1` が根拠です。このスクリプトはその二つの実行ファイルとロゴだけをコピーします。一つ目の文は、設定画面の説明 (サービスはアプリと一緒に起動し、アプリを閉じると止まる) と、パッケージの中身に基づきます。[所有者] ウィンドウを閉じると `miasma.exe` も止まることを、実際のパソコンで確かめてください。

マニフェストには `uap10:RuntimeBehavior="packagedClassicApp"` と `uap10:TrustLevel="mediumIL"` もあります (昇格しない、通常のユーザー権限のプロセスです)。

## 5. パッケージ ID と MSIX のビルド

先に Partner Center でアプリ名を予約します。そのうえで三つの値をビルドに写します。

| Partner Center の値 | 見つかる場所 | スクリプトの引数 | 環境変数 |
|---|---|---|---|
| Identity Name (Package/Identity/Name) | アプリとゲーム、対象のアプリ、製品管理、製品 ID | `-PackageIdentityName` | `MIASMA_STORE_IDENTITY_NAME` |
| Publisher (Package/Identity/Publisher。`CN=...` の文字列) | 同じ画面 | `-Publisher` | `MIASMA_STORE_PUBLISHER` |
| 発行元の表示名 (Package/Properties/PublisherDisplayName) | 同じ画面 | `-PublisherDisplayName` | `MIASMA_STORE_PUBLISHER_DISPLAY_NAME` |

Partner Center のメニュー名は時期によって変わります。三つの値が出ている画面を探してください。Publisher の文字列は一字も違えずに貼り付けます。一文字でも違うと Store はパッケージを拒否します。

ビルドの手順です。

```powershell
.\scripts\build-release.ps1                      # dist\miasma-desktop.exe, miasma.exe, miasma-bridge.exe を作ります
.\scripts\build-store-msix.ps1 `
  -PackageIdentityName "<Identity Name>" `
  -Publisher "<表示どおりの CN=...>" `
  -PublisherDisplayName "<発行元の表示名>"
```

- 入力フォルダー: 既定は `dist` です (`-InputDir`)。64 ビットの `miasma-desktop.exe` と `miasma.exe` が要ります。スクリプトが確認します。`miasma-bridge.exe` はパッケージに入りません。
- 出力: `dist\store\miasma-<version>-windows-x64.msix` と `.sha256` ファイルです。
- バージョン: `-PackageVersion` を渡さないと、ワークスペースのバージョン X.Y.Z が `1.X.(Y*100+Z).0` になります。現在のワークスペースのバージョンは 0.3.2 なのでパッケージのバージョンは `1.0.302.0` です。四つ目の数字は Store 用に 0 でなければなりません。
- 署名: アップロードには要りません。受理されたパッケージには Store が署名します。手元のインストール試験には、`-Publisher` と同じサブジェクトのテスト用証明書の拇印を `-CertThumbprint` に渡します。
- 新しい Windows SDK (`makeappx.exe`) が必要です。マニフェストは `Microsoft.VCLibs.140.00.UWPDesktop` に依存し、これは Store が利用者の側にインストールします。

マニフェストの内容は次のとおりです。最低 Windows は 10.0.19041.0、x64 のみ、リソース言語は `en-us` と `ja-jp`、ロゴは `StoreLogo.png` (50 x 50)、`Square44x44Logo.png`、`Square150x150Logo.png` です。[所有者] アプリには簡体字中国語もあります。その言語を掲載するなら、`installer/msix/AppxManifest.template.xml` に `<Resource Language="zh-cn" />` を加えてください。Partner Center が、この 3 点より大きなストア用ロゴを求めることもあります。最新の一覧を確認してください。

## 6. 認定のチェックリスト

素の Windows 10 か 11 の x64 パソコン (開発ツールの入っていないもの) で行います。

1. 上の手順で MSIX をビルドします。
2. 手元のインストール試験: `-CertThumbprint` を付けて一度ビルドし、署名したパッケージをインストールします。Miasma を起動し、初回にノードを設定し、試験用の連絡先を追加して、小さなファイルを送ります。
3. ウィンドウを閉じます。タスクマネージャーで `miasma.exe` も終了していることを確かめます。
4. アプリが初めて待ち受けを始めるとき、Windows がネットワークの許可を尋ねることがあります。許可して、アプリが動くことを確かめます。
5. Windows App Certification Kit (Windows SDK に入っています) で、`.msix` に Windows デスクトップアプリの試験をかけます。コマンドプロンプトでは `appcert.exe reset` のあとに `appcert.exe test -appxpackagepath <file.msix> -reportoutputpath <report.xml>` を実行します。画面から操作することもできます。失敗はすべて直し、レポートを保管してください。
6. アンインストールして、ディスクに何が残るかを確かめます。プライバシーポリシーのデータフォルダーの説明と照らします。
7. 署名していないパッケージをアップロードします。入力するのは年齢区分、プライバシーポリシーの URL、上の理由の説明、価格 (無料)、掲載文、スクリーンショット、認定担当者への備考です。
8. 認定担当者への備考には次のように書きます。「互いに連絡先へ追加した利用者どうしのピアツーピアのファイル共有です。提供者が運用するサーバーに内容は保存されません。ベータ版です。」

## 7. 審査で問題になりそうな点とアプリの対応

| 懸念 | アプリの対応 | 足りないもの |
|---|---|---|
| ピアツーピアのファイル共有は、違法な内容の共有に使われるおそれがあると見られる | 内容がやり取りされるのは、互いに連絡先に追加した人どうしだけです。検索も、公開の一覧も、知らない人を見つける手段もありません。Store 用のパッケージは BitTorrent のブリッジを含みません。すべて暗号化され、提供者にはサーバーがなく、内容を預かることもできません。 | 提供者に届く通報のボタンはありません。提供者のサーバーがないためです。プライバシーポリシーは GitHub の Issues を案内しています。[所有者] ユーザー作成コンテンツに関する Store の規約の文面を確認し、審査担当者への備考に反映してください。 |
| アプリが GitHub から自分で更新する (Store の外) | 設定の「更新」に、オフ、通知 (初期設定)、自動の三つがあります。 | 初期設定は通知で、起動時に確認します。MSIX パッケージとして動いているときに、これを切るコードはソースにありません。Store の規約は一般に、Store のアプリを Store が更新することを求めます (最新の文面を確認してください)。MSIX のインストール先は読み取り専用でもあります。審査に落ちる原因として最も可能性が高い点です。提出の前に、コードの変更が要ります。Store 版は更新オフで出し、その設定欄は隠します。 |
| インポートのタブの説明に BitTorrent (マグネットリンクとトレントファイル) が出る | ブリッジのプログラムがパッケージに入っていないので、インポートは動きません。マニフェストは、ファイルやリンクの関連付けを登録しません。 | このタブは Technical モードのタブ一覧にあり、ソースはマグネットやトレントを渡されたときにも開きます。[所有者] パッケージ版で、審査担当者がそこへ行けるかを実際のパソコンで確かめてください。行けるなら、動かない機能が見えてしまいます。 |
| ネットワークへのアクセスと待ち受けのソケット | Windows が選んだ UDP ポートですべてのインターフェイスを待ち受け、外へは中継サーバーに接続します。掲載文と理由の説明に、そのことを書いています。 | 初回の起動で、Windows にネットワーク許可の確認が出ます。 |
| 制限付きの機能 runFullTrust | 4 章の理由の説明。 | 審査担当者が詳細を尋ねることがあります。 |
| データ消去が、証拠隠滅の道具に見える | 設定の「緊急消去」は、アプリ自身のデータを端末から消すものとして説明しています。消えないものも書いてあります。 | 説明は中立にしてください。「証拠を消す」とは書かないでください。 |
| セキュリティの表現 | 掲載文はベータ版で、監査を受けていないことを書いています。 | アプリが裏づけられない表現を足さないでください。 |
